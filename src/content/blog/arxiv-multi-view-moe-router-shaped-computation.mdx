## The Gap

Sparse Mixture-of-Experts (MoE) architectures (pioneered by Switch Transformers, Mixtral, and DeepSeek-V2/V3) scale parameter capacity while keeping per-token inference FLOPs constant by routing each token to a top-$k$ subset of experts.

However, standard MoE models operate under a persistent, unaddressed structural limitation: **the router-utility disconnect**.

1. **Weak Correlation in Deep Layers**:
   - In conventional architectures, a single linear routing head computes routing logits and selects experts via top-$k$ gating.
   - However, dense empirical evaluation reveals that the **Spearman rank correlation between single-router scores and true empirical expert utility ($L_2$ activation norm)** drops drastically throughout the network, falling below $\rho < 0.05$ in middle and deep layers.
   - Because unselected experts receive no direct gradient feedback from that token, poor routing decisions become self-reinforcing traps.

2. **The Dilemma of Enriching Expert Signals**:
   - Prior attempts to improve routing fall into costly computational traps:
     - *Activation-based routing* (e.g., AoE) requires preliminary forward passes through all experts to measure intermediate activations before selection, inflating FLOPs.
     - *Multi-representation approaches* (e.g., token slicing or duplicate branches) process multiple hidden vectors through the same expert, multiplying expert computation and all-to-all communication volume across tensor-parallel ranks.

```
                    THE TRADITIONAL MOE BOTTLENECK

  Hidden State h
        │
   [Single Router] ──> Spearman rho < 0.05 with true expert utility in deep layers!
        │
   Top-k Selection
        │
        ├──> Expert E_1(h)  ──┐
        ├──> Expert E_2(h)  ──┼──> Weighted Sum ──> Output y
        └──> Expert E_k(h)  ──┘
        
  * PROBLEM: All selected experts receive the EXACT SAME input vector h,
    ignoring why each expert was chosen by the routing mechanism!
```

## The Increment

**One sentence**: Multi-View MoE aggregates independently initialized sigmoid routers to rectify expert ranking, and reuses their relative preferences to mix a basis of shared latent views into expert-tailored inputs—achieving higher downstream accuracy and lower training loss under a strictly fixed budget of active experts, FLOPs, and communication.

```
                              MULTI-VIEW MOE ARCHITECTURE

                     Hidden State h (Dimension d)
                    ┌──────────────┴──────────────┐
                    │                             │
                    ▼                             ▼
        [Shared Projection Basis]         [Multi-Router Submodule]
       P_1 h, P_2 h, ..., P_K h           R independent router heads
           (K latent views)               s_{m,i} = sigmoid(w_m,i^T h)
                    │                             │
                    │               ┌─────────────┴─────────────┐
                    │               ▼                           ▼
                    │       Sum Across Routers:         Normalize Across
                    │        s_bar_i = sum_m s_m,i       Routers (per expert):
                    │               │                   a_m,i = s_m,i / sum_n s_n,i
                    │               ▼                           │
                    │       Top-k Selection S                   │
                    │               │                           │
                    └───────────────┼───────────────────────────┘
                                    │
                                    ▼
                         [Latent View Mixing]
             For each selected expert i in S:
             v_hat_i = sum_{m=1}^K a_m,i * (P_m h)
                                    │
                                    ▼
                         [Expert Forward Pass]
             Exactly ONE forward pass per active expert: E_i(v_hat_i)
                                    │
                                    ▼
                         [Routed Output Gating]
                     y = sum_{i in S} g_i * E_i(v_hat_i)
```

## The Anatomy

### 1. Multi-Router: Aligning Routing with Utility

Instead of relying on a single fallible gating vector, Multi-Router instantiates $R$ independently parameterized routing heads $\{w^{(m)}\}_{m=1}^R$. For hidden state $h$, router $m$ outputs a sigmoid score for expert $i$:
$$s_{m,i} = \sigma\left({w^{(m)}_i}^\top h\right)$$

The aggregate score for expert $i$ is obtained by summing across routers and adding the load-balancing bias $b_i$:
$$\bar{s}_i = \sum_{m=1}^R s_{m,i}$$
$$\mathcal{S} = \text{TopK}_k(\bar{s} + b)$$

During training, these independent routers naturally differentiate: one router learns fine-grained syntactic boundaries while another tracks semantic reasoning roles. An expert can be selected if it is strongly favored by one specialist router or jointly endorsed by consensus across multiple routers.

### 2. Multi-View Input Modulation

Standard MoE feeds the identical projection $P h$ to every active expert. Multi-View MoE introduces a shared bank of $K$ linear projection matrices $\{P_m\}_{m=1}^K$, generating $K$ distinct latent views:
$$v^{(m)} = P_m h \in \mathbb{R}^{d_{\text{latent}}}$$

For each selected expert $i \in \mathcal{S}$, Multi-View computes **convex mixing coefficients** by normalizing expert $i$'s scores across the $R$ routers (where $R = K$):
$$a_{m,i} = \frac{s_{m,i}}{\sum_{n=1}^R s_{n,i}}, \quad \sum_{m=1}^K a_{m,i} = 1$$

The input $\hat{v}_i$ delivered to expert $E_i$ is the convex combination of the latent views:
$$\hat{v}_i = \sum_{m=1}^K a_{m,i} v^{(m)}$$

This is mathematically equivalent to dynamic, token- and expert-dependent effective projection:
$$P_{\text{eff},i}(h) = \sum_{m=1}^K a_{m,i}(h) P_m, \quad \hat{v}_i = P_{\text{eff},i}(h) h$$

### 3. Output Aggregation and Computational Invariance

The final routed output combines expert computations with normalized output gates $g_i$:
$$y = \sum_{i \in \mathcal{S}} g_i E_i\left(\sum_{m=1}^K a_{m,i} v^{(m)}\right)$$
where $g_i = \text{Softmax}_{i \in \mathcal{S}}(\bar{s}_i \cdot \alpha_i)$ and $\alpha_i$ is a learned per-expert routing scale.

**Crucial Engineering Guarantee**:
- **Active Experts**: Exactly $k$ experts are selected.
- **Compute FLOPs**: Each selected expert executes **exactly one** forward pass.
- **Communication**: Inter-device token dispatch and reduction transfer vectors of size $d_{\text{latent}}$, identical to standard latent-space MoE. The all-to-all communication volume does not increase.

### 2. Router-Utility Alignment and Training Convergence

- **Correlation Improvements**: Multi-Router improves the global Spearman rank correlation between router scores and empirical expert utility by **+8.1%**, and achieves an astounding **+58% relative improvement** in the deep layer with the worst baseline single-router alignment.
- **Late-Stage Loss**: Over the final 1,000 steps of pretraining:
  - Baseline loss: $2.25621$
  - Multi-Router loss: $2.25047$ ($\Delta = -5.74 \times 10^{-3}$)
  - Multi-View loss: $2.24883$ ($\Delta = -7.38 \times 10^{-3}$)
- **Input Permutation Ablation**: Permuting the view-mixing weights $a_{m,i}$ across selected experts increases held-out negative log-likelihood (NLL) by $0.01340$ nats/token, proving that experts actively specialize on token-specific modulated representations.

## Key Takeaways

1. **Routing Should Shape Computation, Not Just Selection**: In traditional MoE, routing scores are discarded after selecting experts and scaling their outputs. Multi-View MoE demonstrates that routing preferences can modulate expert input representations directly, unlocking substantial representational diversity.
2. **Zero Inefficiency MoE Scaling**: Unlike approaches that duplicate computation or require extra matrix multiplications inside FFNs, Multi-View MoE performs convex mixing on pre-dispatch latent vectors. It preserves active parameters, FLOPs, and all-to-all communication budgets.
3. **Significant Reasoning Gains on GPQA**: The massive **+5.60 percentage point jump on GPQA** demonstrates that deep multi-step scientific reasoning benefits disproportionately from multi-router disambiguation and expert input specialization.

## 核心痛点与背景

稀疏混合专家模型（Sparse Mixture-of-Experts, MoE，如 Switch Transformers、Mixtral、DeepSeek-V2/V3）通过将每个 Token 动态路由至参数子集（Top-$k$），实现了在保持单 Token 计算 FLOPs 不变的前提下大幅扩张模型参数容量。

然而，工业界与学术界目前采用的传统 MoE 架构存在一个长期被忽视的底层结构性缺陷：**路由器打分与专家真实效用的严重脱节**。

1. **深层网络的“盲目路由”困境**：
   - 传统 MoE 依靠单组线性路由头（Single Router）计算 Token 对各专家的匹配打分，并通过 Top-$k$ 门控选出激活专家。
   - 然而，论文的密集实证评估表明：在网络的中层和深层，**单路由器的排序打分与专家真实的经验效用（以专家激活输出的 $L_2$ 范数衡量）之间的斯皮尔曼秩相关系数（Spearman $\rho$）断崖式下跌，甚至降至 0.05 以下**。
   - 未被选中的专家无法从当前 Token 获取任何梯度反馈，导致错误的路由决策在训练过程中形成自我强化的负向循环。

2. **丰富专家表征与计算成本的两难悖论**：
   - 现有的改进尝试往往陷入巨大的计算惩罚：
     - *基于内部激活的路由*（如 AoE）：需要所有专家先执行前向投影计算才能获取选拔信号，破坏了稀疏计算的能效。
     - *多重表征/切片路由*：将 Token 拆解为多个子 Token 分别通过专家计算，导致专家的前向计算次数和跨卡 All-to-All 通信开销成倍暴增。

```
                    传统 MOE 架构的根本性瓶颈

  隐藏层状态 h
        │
   [单线性路由器] ──> 在中深层，与专家真实输出效用相关性 rho < 0.05！
        │
   Top-k 门控选择
        │
        ├──> 专家 E_1(h)  ──┐
        ├──> 专家 E_2(h)  ──┼──> 加权求和 ──> 输出 y
        └──> 专家 E_k(h)  ──┘
        
  * 痛点：所有被选中的专家接收到的都是完全相同的一张输入特征向量 h，
    路由器在做出选择后，其蕴含的丰富偏好信息即被直接丢弃！
```

## 核心技术实现

### 1. Multi-Router：多视角独立路由器

Multi-Router 摒弃了脆弱的单路由头，部署了 $R$ 个独立参数化的 Sigmoid 路由头 $\{w^{(m)}\}_{m=1}^R$。对于输入特征 $h$，第 $m$ 个路由器对第 $i$ 个专家的匹配打分为：
$$s_{m,i} = \sigma\left({w^{(m)}_i}^\top h\right)$$

最终专家总分由各路由头求和并加上负载均衡偏置项 $b_i$ 决定：
$$\bar{s}_i = \sum_{m=1}^R s_{m,i}$$
$$\mathcal{S} = \text{TopK}_k(\bar{s} + b)$$

训练实证表明，独立初始化的多个路由头会自发演化出高度差异化的专长偏好：有的路由头专注于局部句法模式，有的路由头专注于跨步长语义推理。这使得被某个路由头极力看好、或被多个路由头共同认可的专家均能入选。

### 2. Multi-View 潜在视角输入调制

传统 MoE 给所有入选专家传入相同的投影向量 $P h$。Multi-View MoE 设置了 $K$ 个低维共享线性投影基底 $\{P_m\}_{m=1}^K$，生成 $K$ 个潜在特征视角：
$$v^{(m)} = P_m h \in \mathbb{R}^{d_{\text{latent}}}$$

对于每一个选中的专家 $i \in \mathcal{S}$，Multi-View 利用该专家在各路由器上的得分比例，计算该专家的**凸混合系数（Convex Mixing Weights）**（其中 $R = K$）：
$$a_{m,i} = \frac{s_{m,i}}{\sum_{n=1}^R s_{n,i}}, \quad \sum_{m=1}^K a_{m,i} = 1$$

随后直接在输入端合成该专家的定制化潜在表征：
$$\hat{v}_i = \sum_{m=1}^K a_{m,i} v^{(m)}$$

这在数学上等价于为每个 Token-专家对动态生成了一个有效投影矩阵：
$$P_{\text{eff},i}(h) = \sum_{m=1}^K a_{m,i}(h) P_m, \quad \hat{v}_i = P_{\text{eff},i}(h) h$$

### 3. 严格的零计算开销保障（Zero Computational Overhead）

最终专家输出聚合如下：
$$y = \sum_{i \in \mathcal{S}} g_i E_i\left(\sum_{m=1}^K a_{m,i} v^{(m)}\right)$$
其中 $g_i = \text{Softmax}_{i \in \mathcal{S}}(\bar{s}_i \cdot \alpha_i)$，$\alpha_i$ 为专家缩放因子。

**工程硬指标保证**：
- **激活专家数量**：严格保持为预设的 $k$ 个专家。
- **计算复杂度**：每个入选专家仅执行**一次**前向计算，FFN 算力消耗与基础 LatentMoE 严格一致。
- **通信带宽**：跨卡张量传输的输入向量维度保持为 $d_{\text{latent}}$，跨 GPU 的 All-to-All 通信数据量毫厘未增。

## 启示与实践意义

1. **路由不仅决定“由谁算”，更应塑造“算什么”**：传统架构在 Top-$k$ 门控选拔结束后便丢弃了精细的路由权重；Multi-View MoE 证明路由器的多头偏好是极其廉价而强大的表征调制源。
2. **零硬件开销的架构升级范式**：在十亿乃至万亿级大模型的分布式部署中，任何通信量或重复计算的增加都是不可接受的。Multi-View 仅在本地做向量加权混合，不改动任何 All-to-All 通信和专家内部核函数，非常适合工业级大规模复现。
3. **GPQA 暴涨 5.6% 的深远影响**：专家在输入端的解耦调制为复杂科学推理提供了更丰富的专业特征通道，为后续开源大模型（如 DeepSeek 系列迭代）在架构层提供了极具借鉴价值的演进方向。
