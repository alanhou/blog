## The Gap

Despite rapid advances in frontier reasoning models (e.g., DeepSeek-R1, GPT-o-series, Gemini-Thinking), large language models (LLMs) continue to stumble on intricate, multi-step mathematical problems. A critical bottleneck is their inability to reliably **self-correct**: when asked to reflect on their own mistakes, LLMs frequently fall into hallucinations, "confirming" invalid solutions or rewriting correct answers into incorrect ones (negative damage transitions $C \to W$).

Existing verification paradigms predominantly operate in a single direction, each harboring fatal structural blind spots:
1. **Backward Verification (Answer-to-Constraint)**: Starts from the proposed final answer and substitutes it back into the original problem constraints (e.g., ProgCo).  
   *The Blind Spot*: Passing surface-level constraints does not guarantee that the reasoning path was logically valid, nor does it guarantee **objective completeness** (e.g., finding *all* valid roots, non-trivial boundary solutions, or global extrema).
2. **Forward Verification (Premise-to-Conclusion)**: Reads the solution step by step from problem conditions, verifying each deduction sequentially (e.g., Process Reward Models / PRMs).  
   *The Blind Spot*: On long reasoning chains, forward checkers suffer from error accumulation and cognitive drift, frequently losing sight of global boundary constraints or accepting plausible-sounding but mathematically vacuous intermediate claims.

```
                    THE UNIDIRECTIONAL VERIFICATION DILEMMA

  Problem q: Solve f(x) = 0 under global constraints C

  [Backward Verification]:
  Answer a_0 ──> Check against constraints C?
  ├── Pros: Bypasses complex intermediate algebraic drift.
  └── Cons: Blind to faulty reasoning paths and missing root sets (e.g., missed x_2).

  [Forward Verification]:
  Condition q ──> Step 1 ──> Step 2 ──> ... ──> Step K
  ├── Pros: Checks local logical entailment (q ∧ c_1 ... |= c_k).
  └── Cons: Accumulates verification error on long chains; easily overlooks global invariants.

  Missing Piece: How to close the loop between both directions without invalidating states?
```

## The Increment

**One sentence**: Renmin University researchers propose **BiVerify**, an agentic mathematical verification system that establishes a formal state machine coordinating backward constraint checking and forward claim entailment over the exact same solution candidate, dynamically managing direction switching, candidate updates, and state resets while offloading exact calculations to shared symbolic tools.

## Core Framework & Mechanisms

### 1. Bidirectional Scheduling State Machine
BiVerify formulates verification as a closed-loop discrete dynamical system. For candidate $C_t = (q, y_t, a_t)$ at turn $t$, the scheduling state is:
$$\Sigma_t = (C_t, B_t, F_t, d_t)$$
where $B_t, F_t \in \{\text{Unknown}, \text{Pass}, \text{Fail}\}$ represent the directional verification verdicts, and $d_t \in \{B, F\}$ is the active direction.

The system enforces a strict **Joint Acceptance Criterion**:
$$\text{Accept}(C_t) \iff B_t = \text{Pass} \wedge F_t = \text{Pass}$$
Crucially, pass states are candidate-bound: if candidate $C_i$ passes backward checks and an updated proposal $C_j$ ($j \neq i$) passes forward checks, **neither is accepted**. Prior verification records are wiped whenever a candidate is updated, preventing cross-candidate state pollution.

The scheduling transition function $S(\Sigma_t, s_t, \hat{C}_t)$ follows:
$$S(\Sigma_t, s_t, \hat{C}_t) = \begin{cases}
\textbf{Accept}, & \text{if } B_t = F_t = \text{Pass} \\
\textbf{Switch}, & \text{if } s_t = \text{Pass} \wedge \neg\text{Accept}(C_t) \\
\textbf{Update}, & \text{if } s_t = \text{Fail} \wedge \hat{C}_t \neq C_t \\
\textbf{Refine}, & \text{if } s_t = \text{Fail} \wedge \hat{C}_t = C_t
\end{cases}$$

- **Switch**: Switches $d_t \to \text{Other}(d_t)$ to verify the complementary direction.
- **Update**: Adopts the revised solution $C_{t+1} \leftarrow \hat{C}_t$ and resets both states $B_{t+1} = F_{t+1} = \text{Unknown}$.
- **Refine**: Fixes ambiguous verification workflows without altering the candidate.

### 2. Backward & Forward Verification Agents
- **Backward Adjudication**: Decomposes problem $q$ into explicit algebraic, boundary, and domain constraints. The proposed answer $a_t$ is back-substituted. Mathematical tools (SymPy, Z3 SMT solver) evaluate satisfaction symbolically.
- **Forward Step Entailment**: Extracts an ordered list of key intermediate claims $K_t = \{c_{t,1}, c_{t,2}, \dots, c_{t,n}\}$. Each claim is verified under semantic entailment:
  $$q \wedge c_{t,1} \wedge \dots \wedge c_{t,i-1} \models c_{t,i}$$
  If claim $k_t$ fails, verification halts immediately, pinpointing $c_{t,k_t}$ as the exact source of error to guide surgical correction.

```
                      FORWARD CLAIM ENTAILMENT CHAIN

  Problem q: "Find all real roots of x^4 - 5x^2 + 4 = 0"
  
  Claim 1: Let u = x^2, then u^2 - 5u + 4 = 0     ──> [Entailed] ✓
  Claim 2: Roots for u are u = 1 and u = 4        ──> [Entailed] ✓
  Claim 3: Since u = x^2, x = ±1 and x = ±2       ──> [Entailed] ✓
  Claim 4: Completeness: Exactly 4 distinct roots ──> [Entailed] ✓
                                                      Verdict: Pass
```

## Practical Implications

1. **The Fallacy of Unidirectional Self-Correction**: Relying on prompting LLMs to "check your work" forwards or backwards alone hits a hard ceiling. Bidirectional cross-examination is fundamentally necessary to catch both logic derivation errors and boundary constraint violations.
2. **Strict Candidate-State Isolation**: Self-correction pipelines must treat verification states as strictly coupled to candidate identities. Allowing "partial pass" signals to linger across revised text introduces hallucinated confidence and destabilizes reasoning loops.
3. **Synergy Between Thinking Models and Symbolic Oracles**: Decoupling fuzzy reasoning (handled by the LLM) from exact algebraic computation and constraint satisfiability (handled by SymPy / Z3) eliminates arithmetic calculation noise, letting the verifier focus purely on logical rigor.

## 核心痛点：大模型数学自我纠错的“单向死局”

以 DeepSeek-R1、OpenAI o-系列以及 Gemini-Thinking 为代表的前沿推理模型，虽然在长思维链（CoT）推理上取得了长足进步，但在面对复杂的奥数及前沿高维数学问题时，仍然极易出现细微而致命的逻辑失误。更严峻的是，当让大模型对自己的解题过程进行“反思与自我纠错（Self-Correction）”时，模型往往陷入**虚假自洽**：不仅无法纠正错误，反而常常把原本正确的题目改错（即所谓的负向修正 $C \to W$ 损伤）。

究其根本，现有自我纠错方法主要依赖单向验证，存在不可逾越的结构性缺陷：
1. **逆向验证（Backward Verification，以答案代入约束）**：从候选答案出发，直接代入原题的边界条件与约束方程中核验（例如 ProgCo 代码校验）。  
   *致命盲区*：即便答案偶然吻合显式约束，也完全无法保证**推导过程的数学完备性与逻辑严密性**。例如在求解多解方程、极值或离散组合时，逆向验证极易漏掉有效根或边界解（无法核验“是否求出了全部解”）。
2. **正向验证（Forward Verification，从条件顺推推导）**：沿着题干条件与解答步骤，逐行推演每一步逻辑蕴含（例如过程奖励模型 PRM）。  
   *致命盲区*：在超长推导链条下，正向验证极易遭受认知漂移与误差累积；检查者容易陷入繁复的代数代换中，反而“一叶障目”忽略了题干最底层的全局守恒量与隐式定义域约束。

```
                     单向数学验证的互补性与结构盲区

  题目 q: 在全局约束 C 下求解方程 f(x) = 0 的所有解

  【逆向验证】：从候选答案 a_0 倒推回原题约束 C
  ├── 优势：跳过冗长复杂的中间代数变换，直接核验结果合法性；
  └── 缺陷：对推理过程中的逻辑跳步、虚假推论、以及“解集完整性”完全盲目（漏根无法察觉）。

  【正向验证】：题干条件 q ──> 步骤 1 ──> 步骤 2 ──> ... ──> 最终推论
  ├── 优势：严格核查局部逻辑蕴含（q ∧ c_1 ... |= c_k），精准定位步骤错误；
  └── 缺陷：在长链推导下极易误差累积，对全局边界条件的约束全局把控力薄弱。

  破局之钥：如何构建严密的双向闭环机制，使正反两向验证无缝协调、状态严格对齐？
```

## 核心机制与数学建模

### 1. 严格绑定的调度状态机（Scheduling State Machine）
BiVerify 彻底改变了传统自我纠错中“随意覆盖、状态不清”的混乱逻辑，在第 $t$ 轮迭代中将候选解答 $C_t = (q, y_t, a_t)$ 的验证状态形式化定义为四元组：
$$\Sigma_t = (C_t, B_t, F_t, d_t)$$
其中：
- $B_t, F_t \in \{\text{Unknown}, \text{Pass}, \text{Fail}\}$ 分别记录当前候选在逆向（Backward）与正向（Forward）维度的裁决结果。
- $d_t \in \{B, F\}$ 为当前激活的验证方向。

系统确立了绝对刚性的**联合接受准则（Joint Acceptance Criterion）**：
$$\text{Accept}(C_t) \iff B_t = \text{Pass} \wedge F_t = \text{Pass}$$
**关键定理：验证状态与候选解具有强物理绑定性。** 若解答 $C_i$ 仅通过了逆向核验，而系统在修改后生成了新解答 $C_j$并通过了正向核验，系统**绝不认可**两者的拼接，必须触发状态彻底清空，确保最终采纳的解答在**同一个静态版本**上同时通过双向检验。

调度函数 $S(\Sigma_t, s_t, \hat{C}_t)$ 执行状态转移：
$$S(\Sigma_t, s_t, \hat{C}_t) = \begin{cases}
\textbf{Accept}, & \text{当且仅当 } B_t = F_t = \text{Pass} \\
\textbf{Switch}, & \text{当前方向通过但未完全闭环，切换至互补方向 } \text{Other}(d_t) \\
\textbf{Update}, & \text{当前方向报错且产生新候选 } \hat{C}_t \neq C_t \implies \text{重置 } B_{t+1} = F_{t+1} = \text{Unknown} \\
\textbf{Refine}, & \text{报错源于验证流程自身定义不清，修正流程后重试当前方向}
\end{cases}$$

### 2. 逆向约束解构与正向断言蕴含
- **逆向验证模块**：先于正向执行。将原题条件拆解为显式代数等式、不等式与值域边界；将候选答案直接代入，调用 SymPy 或 Z3 求解器执行精确的符号真值检验。若代入不合规，无需执行昂贵的正向推演，即可立刻打回修改。
- **正向推演模块**：从解答中抽取拓扑有序的关键断言链 $K_t = \{c_{t,1}, c_{t,2}, \dots, c_{t,n}\}$。逐级验证局部语义蕴含（Semantic Entailment）：
  $$q \wedge c_{t,1} \wedge \dots \wedge c_{t,i-1} \models c_{t,i}$$
  一旦第 $k_t$ 个断言出现逻辑裂痕，验证立即终止并返回断言失败快照，为修改模块提供靶向手术级错误定位。

```
                     正向断言链的逐步语义蕴含示例

  题目 q: "求方程 x^4 - 5x^2 + 4 = 0 在实数范围内的所有根"
  
  断言 1: 设 u = x^2, 原方程转化为二次方程 u^2 - 5u + 4 = 0 ──> [蕴含成立] ✓
  断言 2: 解得根为 u = 1 或 u = 4                           ──> [蕴含成立] ✓
  断言 3: 由 x^2 = 1 得 x = ±1; 由 x^2 = 4 得 x = ±2         ──> [蕴含成立] ✓
  断言 4: 完备性检查: 四次多项式在实数域内至多 4 根，解集完备   ──> [蕴含成立] ✓
                                                               正向裁决: Pass
```

## 实践启示与工程落地

1. **废弃粗暴的“让模型自行反思”模式**：单纯给 LLM 提示词施加“请检查你的答案”只能诱导模型陷入确认偏误。必须在工程上将正向逻辑蕴含与逆向约束回代解耦并闭环控制。
2. **严防跨轮次状态污染**：自我纠错智能体系统在更新解答文本时，必须以形式化状态机将历史核验记录完全失效；任何“由于前一版本逆向通过，故新版本直接免检”的偷懒优化，都会直接导致严重幻觉。
3. **大模型负责抽象逻辑，符号求解器负责硬算**：将 SymPy 与 Z3 作为底层算力工具嵌入正反验证链路，使大模型彻底解放出容易出错的数值乘除与高阶因式分解，聚焦于宏观证明策略与语义推理。
