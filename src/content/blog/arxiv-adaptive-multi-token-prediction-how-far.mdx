## The Gap

Multi-Token Prediction (MTP)—spearheaded by architectures like Medusa, Meta's MTP backbones, and Qwen3-MTP—has emerged as one of the most promising frontiers in LLM inference acceleration. By training auxiliary prediction heads to predict tokens $t+1, t+2, \dots, t+H$ concurrently from the current hidden state, MTP generates multi-token candidate blocks that are verified in a single forward pass of the target model.

However, deploying MTP in production environments immediately exposes a severe algorithmic bottleneck: **the fixed-horizon dilemma**.
- In standard autoregressive speculative drafting (such as using a small helper model), an early-stopping rule can halt generation token-by-token whenever drafting confidence drops.
- In MTP, however, **all heads are computed in the exact same forward pass matrix multiplication**. The speculation horizon $H$ must be fixed *before* the drafting step begins!

A static choice of $H$ is fundamentally sub-optimal:
1. *Large $H$ (e.g., $H=5$)*: Delivers massive acceleration on predictable boilerplate code and routine syntax, but catastrophically wastes verification compute during complex mathematical derivations where tokens are rejected at position $t+1$, forcing the engine to evaluate and immediately discard the entire remaining suffix ($t+2 \dots t+5$).
2. *Small $H$ (e.g., $H=2$)*: Safe and conservative, but leaves massive throughput on the table during long, predictable spans.

## The Increment

**One sentence**: AMTP formulates speculation horizon selection in Multi-Token Prediction as an online control problem governed by acceptance survival probabilities, dynamically optimizing the draft length before each step without model retraining to achieve up to 4.1x faster decoding over autoregressive baselines.

### Core Mechanism

AMTP introduces an adaptive controller that sits atop any frozen MTP architecture:

1. **Acceptance Survival Formulation**:
   - For a draft horizon $h \in \{1, \dots, H_{\max}\}$, let $S(h) = \Pr(\text{tokens } 1 \dots h \text{ are all accepted})$ represent the *acceptance survival function*.
   - Because MTP verification uses prefix trees or causal masks, the expected number of committed tokens under horizon $h$ is strictly bounded by:
     $$\mathbb{E}[N_{\text{accept}}(h)] = \sum_{i=1}^h S(i)$$
2. **Online Horizon Optimization**:
   - Let $C(h)$ be the empirical verification cost (in milliseconds) of checking a tree of depth $h$.
   - The theoretical objective is to select the horizon that maximizes the instantaneous throughput:
     $$h^* = \arg\max_{h} \frac{\mathbb{E}[N_{\text{accept}}(h)]}{C(h)}$$
   - AMTP trains an ultra-lightweight linear controller via **Online Gradient Descent (OGD)**. After every verification pass, the verifier's ground-truth acceptance mask serves as instant supervision to update the controller's survival estimates.
3. **Sublinear Throughput Regret**:
   - The authors prove theoretically that the cumulative throughput regret against the clairvoyant context-optimal horizon decays sublinearly: $R_T = \mathcal{O}(\sqrt{T})$.
   - This mathematically guarantees that the controller converges rapidly to the optimal pacing strategy across changing text distributions.
4. **Comprehensive Benchmarking**:
   - Evaluated on Llama-3.1-8B-Instruct (Medusa heads), Meta MTP models, and Qwen3-4B-MTP across demanding reasoning benchmarks (AIME 2025, GSM8K).
   - Achieves up to **4.1x speedup over standard autoregressive decoding**, and consistently beats the best hand-tuned fixed horizon in 8 out of 10 settings (yielding up to **10% net throughput gains** over static baselines).

### Key Concepts

- **Multi-Token Prediction (MTP)**: A transformer architecture featuring multiple auxiliary output heads that simultaneously predict several subsequent tokens in one forward pass.
- **Acceptance Survival**: The monotonic probability curve that a sequence of candidate draft tokens will be accepted consecutively from left to right.
- **Online Horizon Control**: The practice of adjusting the active depth or width of speculative candidate drafts on-the-fly based on ongoing verification signals.

## Framework Shift

```
Before (Static Speculation Windows):
  Design: Choose a single static horizon H (e.g. H=3 or H=4) during deployment.
  Pathology: Massive compute waste on difficult reasoning steps; under-speculation on easy text.
  Tuning: Requires expensive grid searches per dataset and per hardware cluster.

After (AMTP Dynamic Online Adaptation):
  Design: Controller dynamically chooses h* based on context features and real-time survival rates.
  Efficiency: Automatically expands horizon on repetitive syntax; contracts horizon on complex logic.
  Operational Profile: Zero retraining required; plug-and-play across Medusa, Meta MTP, and Qwen MTP.
```

## Takeaways

- Stop using fixed speculation windows for Multi-Token Prediction; drafting confidence fluctuates wildly between boilerplate syntax and complex logic.
- Model acceptance survival explicitly to quantify the exact marginal return of activating deeper prediction heads.
- Deploy online gradient descent controllers (AMTP) at the serving gateway to achieve zero-cost adaptive pacing with provable sublinear regret.

## 缺口

以 Medusa（美杜莎头）、Meta 原生 MTP 架构以及 Qwen3-MTP 为代表的**多 Token 预测（Multi-Token Prediction, MTP）**，正在迅速成为大模型推理加速领域的最强底层技术之一。
与传统依赖外挂小草稿模型的投机采样不同，MTP 直接在主干网络顶部并行挂载多个预测头，在单次前向传播中同时生成未来 $t+1, t+2, \dots, t+H$ 个 Token 的候选树，并在主模型的单次验证前向中完成并行核验。

然而，当工程师尝试将 MTP 部署至真实的高并发服务集群时，立刻撞上了一个严峻的架构死结——**静态视界困境（Fixed-Horizon Dilemma）**。
- 在传统的自回归小模型草稿方案中，草稿模型是一个词一个词串行生成的，因此可以根据置信度随时动态刹车（Early Stopping）；
- 但在 MTP 中，**所有预测头的矩阵乘法是在同一个前向计算核（Kernel）中全并发启动的**！这意味着投机视界 $H$（往前看几步）必须在草稿生成启动前就被硬编码死死写定！

采用固定的静态视界 $H$ 必然导致极其严重的算力错位与浪费：
1. *视界设得太大（如 $H=5$）*：面对标准 Python 语法模板或常见客套话时能够实现极致加速；但在高难度数学推导或严密逻辑分支中，大模型往往在第 2 个 Token 处就发生拒绝，导致后序耗费显存带宽计算出来的 $t+3 \dots t+5$ 个 Token 被瞬间全盘作废抛弃，**严重白白浪费了验证算力**。
2. *视界设得太小（如 $H=2$）*：虽然保守安全，但在面对大段高度可预测的自然语言与规范代码时，白白错失了大幅压榨吞吐的黄金窗口。

## 增量

**一句话**: 本文将多 Token 预测（MTP）中的投机视界选择形式化为在线控制理论问题，提出了 AMTP 自适应控制器：在无需重新训练基座模型的前提下，通过在线梯度下降实时预测前缀的「接收存活概率」，实现相比标准自回归解码高达 4.1 倍的推理加速，并在 80% 的实测任务中稳定超越任何经过人工精心调优的静态窗口基准。

### 核心机制

AMTP 在完全冻结的 MTP 骨干网络外层，构筑了一套极其精巧的在线控制闭环：

1. **接收存活函数（Acceptance Survival Function）的数学建模**：
   - 设候选视界为 $h \in \{1, \dots, H_{\max}\}$，定义前缀全部被验证通过的联合概率为存活率 $S(h) = \Pr(\text{Tokens } 1 \dots h \text{ 全部被接收})$。
   - 由于验证过程严格遵循前缀连续性，激活视界 $h$ 所带来的期望接收 Token 收益具有严谨的积分形式：
     $$\mathbb{E}[N_{\text{accept}}(h)] = \sum_{i=1}^h S(i)$$
2. **瞬时吞吐收益驱动的在线极值选择**：
   - 设校验深度为 $h$ 的树状结构在硬件上的计算耗时为 $C(h)$。
   - 控制器的目标是在每一步前向计算前，精准捕获使瞬时吞吐（Tokens Per Second）最大化的临界视界：
     $$h^* = \arg\max_{h} \frac{\mathbb{E}[N_{\text{accept}}(h)]}{C(h)}$$
   - AMTP 挂载了一个微型线性判别器，采用**在线梯度下降（Online Gradient Descent, OGD）**。每一次校验完成后，真实的接收掩码（Mask）作为即时无偏标签反向传播，实现「从每一次验证中零成本实时进化」。
3. **理论证明次线性吞吐悔量（Sublinear Regret）**：
   - 作者在数学上证明：在线学习器的预测误差直接映射为相对于全知最优视界的吞吐悔量，且在 OGD 机制下该悔量严格满足次线性上界 $R_T = \mathcal{O}(\sqrt{T})$。
   - 这在理论层面上保证了控制器绝不会在特定分布漂移下陷入发散失控。
4. **横跨主流前沿 MTP 模型的完备验证**：
   - 在 Llama-3.1-8B (Medusa)、Meta MTP 以及 Qwen3-4B-MTP 上展开跨架构评测，直面 AIME 2025、GSM8K 等最高难度推理基准。
   - 相比于原生自回归基线实现最高 **4.1 倍解码加速**；更在 10 组对照实验中的 8 组里，**击败了人类专家耗时耗力调优出的最佳静态视界**，带来最高额外 10% 的纯净吞吐净增益。

### 关键概念

- **多 Token 预测（Multi-Token Prediction, MTP）**：在单个大模型上并行构建多个预测头，使单次前向计算能同时输出多个未来 Token 候选的技术。
- **接收存活率（Acceptance Survival）**：衡量从第一个预测 Token 开始连续通过校验的概率密度衰减函数。
- **在线视界控制（Online Horizon Control）**：摒弃静态写死投机深度的教条做法，依据模型实时推理置信度动态伸缩投机步长的前沿算法机制。
