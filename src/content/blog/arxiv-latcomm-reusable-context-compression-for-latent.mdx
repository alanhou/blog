## The Gap

In compound AI systems, collaborative multi-agent swarms, and enterprise retrieval pipelines, a single massive context—such as an extensive API specification, a medical case file, a legal contract, or a full code repository—frequently serves as the shared reference for dozens or hundreds of downstream questions.

Under current serving paradigms, communication between disparate LLMs relies on **natural language text transmission**: the sender dumps raw text into the receiver's prompt. This introduces a devastating computational redundancy:
- **Redundant Prefill Overhead**: The receiver LLM must process and re-encode the entire multi-thousand-token document from scratch for *every single question*, consuming vast GPU FLOPs and saturating KV cache memory.
- **The Failure of Existing Compression**: Prior latent communication and context compression approaches suffer from crippling structural limits:
  1. *Single-Vector Pooling (e.g., dense embeddings)*: Destroys granular token-level evidence, collapsing accuracy on detailed reading comprehension.
  2. *Query-Dependent Compression (e.g., soft prompting / TTT)*: Compresses the context specifically for *one* query, destroying reusability across future questions.
  3. *Homogeneous Weight Binding*: Requires the sender and receiver to be identical model checkpoints sharing the exact same vocabulary and hidden dimensions.

## The Increment

**One sentence**: LatComm establishes an asynchronous latent communication interface that encodes long textual contexts once into a compact, query-agnostic neural packet, allowing a separate frozen receiver LLM to selectively query the packet via prompt-gated cross-attention—reducing receiver input tokens by 57x and achieving 3x faster end-to-end question answering.

### Core Mechanism

LatComm decouples context digestion into **asymmetric, one-time encoding and query-conditioned selective reading**:

1. **One-Time Query-Agnostic Packetization**:
   - A frozen sender LLM processes the long context document without access to downstream questions.
   - Intermediate activations across landmark positions are downsampled and projected into a fixed-size **Latent Packet** $\mathcal{P} \in \mathbb{R}^{M \times d}$ (where $M \ll N$, typically achieving a $16\times$ to $64\times$ token reduction).
   - This packet is cached in GPU memory or transmitted across nodes as a lightweight tensor payload.
2. **Prompt-Gated Cross-Attention Reading**:
   - The receiver LLM can be a completely different frozen model architecture.
   - When a specific question $\mathbf{q}$ arrives, the receiver generates query vectors that attend to the latent packet through lightweight, trainable cross-attention bridge layers.
   - An in-situ gating module $\mathbf{g}(\mathbf{q})$ computes prompt-dependent attention masks, allowing the receiver to selectively extract needle-level evidence from the packet while ignoring irrelevant background regions.
3. **Completely Frozen Foundation Models**:
   - Neither the sender LLM nor the receiver LLM undergoes weight updates.
   - Only the compact projection adapters and cross-attention gating parameters are optimized, preserving the broad reasoning priors and conversational alignment of both models.
4. **Spectacular Throughput and Accuracy**:
   - Evaluated across 12 demanding multiple-choice QA benchmarks.
   - Outperforms conventional dense single-vector baselines by up to **10.2 percentage points**.
   - On the QuALITY long-context benchmark, LatComm cuts receiver input tokens by **$57\times$**, speeding up document-level question answering by **$3\times$ in wall-clock time**.

### Key Concepts

- **Latent Communication**: Passing internal continuous activation tensors between distinct neural models rather than translating into discrete natural language text tokens.
- **Query-Agnostic Context Packet**: A dense neural representation of a document that retains sufficient entropy to answer arbitrary future questions without being conditioned on a specific query prompt.
- **Prompt-Gated Reading**: An attention mechanism where the incoming question modulates cross-attention weights over pre-computed latent memory slots.

## 缺口

在现代复合 AI 系统（Compound AI Systems）、协同多智能体工作流以及企业级知识库问答中，一个非常普遍的业务场景是：**围绕同一份庞大且结构复杂的长背景文档（例如数十页的行业规范、代码仓库索引、法律合同或临床病历），在短时间内连续向大模型提出数十甚至上百个不同的具体问题**。

在现有的服务与通信架构中，不同模型或智能体之间依然原始地依赖**纯文本字符串传输（Text-based Transmission）**：
发送端将数万 Token 的原始长文本，一次次生硬地拼接在每一个问题的开头，打成 Prompt 喂给接收端大模型。这种做法在底层造成了灾难性的算力黑洞：
- **极其昂贵的重复 Prefill 冗余**：接收端大模型必须针对这 50 个问题，将同一份长达数万 Token 的文档**从头到尾重复执行 50 次前向 Prefill 计算**！显存带宽被彻底吃光，KV Cache 瞬间撑爆，算力成本居高不下。
- **现有上下文压缩技术的局限性**：
  1. *单向量池化压缩（如 Dense Embedding）*：将长文本强行压缩成一个单一向量，微观语义信息严重丢失，面对需要精准定量的细粒度问答完全失灵；
  2. *强依赖具体问题的动态压缩（如 TTT 或特定 Soft-Prompt）*：压缩过程必须提前获知具体问题，无法在后续未见问题上重复使用；
  3. *同源权重强绑定*：往往要求发送端与接收端必须是同一款模型、共享相同的词表与隐层维度。

### 核心机制

LatComm 将笨重的长文档处理切分为**「一次性离线神经封包」与「轻量级在线提示词门控读取」**两大阶段：

1. **与具体问题无关的一体化神经封包（Query-Agnostic Packetization）**：
   - 保持发送端大模型权重全程冻结，在无需知晓下游任何具体问题的前提下，对长上下文进行单次前向传播。
   - 提取跨层特征并经过下采样适配器，凝练成一个紧凑的固定尺寸**潜空间数据包（Latent Packet）** $\mathcal{P} \in \mathbb{R}^{M \times d}$（条目数 $M \ll N$，通常实现 16 到 64 倍的体积骤缩）。
   - 该数据包作为轻量级张量缓存常驻显存，支持跨节点极速分发。
2. **基于提示词门控的 Cross-Attention 动态读取**：
   - 接收端大模型可以是参数、词表完全异构的另一款开源模型。
   - 当具体问题 $\mathbf{q}$ 到达时，接收端基于当前问题的词向量，通过轻量级交叉注意力层扫描预计算好的潜空间数据包。
   - 内置的门控单元 $\mathbf{g}(\mathbf{q})$ 根据问题的语义焦点，自适应计算注意力激活掩码，精准提取出与当前问题强相关的数据包切片，完全过滤背景冗余信息。
3. **两端基座模型全程「零微调」**：
   - 发送端与接收端两款大模型的底层核心权重保持 100% 冻结。
   - 仅训练参数量极其微小的特征映射层与 Cross-Attention 门控，完全保留两端基座模型强大的通用推理、对齐与指令服从能力。
4. **硬核降本与精度验证**：
   - 在涵盖多领域的 12 个多项选择长文本问答数据集上展开系统实测。
   - 相比于传统单向量稠密压缩基线，平均准确率大幅反超高达 **10.2 个百分点**。
   - 在高难度长文本基准 QuALITY 上，LatComm 将接收端处理的输入规模**暴砍 57 倍**，在保持高精度的同时，端到端问答耗时**整整缩短至原先的 1/3**。

### 关键概念

- **潜空间通信（Latent Communication）**：跳过将认知压缩为人类自然语言文字的中间步骤，直接在神经网络高维连续激活张量层面进行跨模型高效信息交互。
- **与问题无关的神经封包（Query-Agnostic Context Packet）**：一种高保真的稠密上下文潜层表征，能够全息封装文档深层信息，供下游任意未知问题随时读取。
- **提示词门控读取（Prompt-Gated Reading）**：利用具体查询语句的意图动态计算门控权重，使模型在跨注意力扫描预计算缓存时具备极高的聚焦分辨力。
